## 二、部署步骤

### 2.1 本地一键（开发/演示）

```powershell
# 0. 前置：JDK17、Node 18+、MySQL 3307（库 uniapp_booking）、Redis 6379
# 1. 依赖 + 后端 + 云函数（自动构建 jar、探活 health、探针 code=0）
powershell -ExecutionPolicy Bypass -File scripts\start_all.ps1 -Rebuild
# 2. H5（5186）
cd 05_代码\frontend; npm install; npm run dev:h5
# 3. 冒烟
powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1
python scripts\smoke_batch3.py ; python scripts\smoke_cf.py
# 4. 停止（不动共享 MySQL/Redis）
powershell -ExecutionPolicy Bypass -File scripts\stop_all.ps1
```

踩过的坑（全部有据）：
- `.ps1` 必须 **UTF-8 with BOM**，否则 Windows PowerShell 按 GBK 解码报 ParserError（失败日志 ⑤/⑦）。
- `start_all.ps1` 默认找容器 `rag-mysql` 的 **3308**；本机实际用原生 **3307**，需以 `MYSQL_PORT=3307` 起后端（后端文档 §6）。
- 后端已在跑时改了 `APP_SECRET` → 云函数探针 40102；先 `stop_all` 再启动。

### 2.2 生产部署（H5）

1. `npm run build:h5` → `dist/build/h5`（exit 0 为判据；`check:build` 断言 6 页）。
2. Nginx 托管静态目录；`env.ts` 的 `API_BASE` 换成生产后端 HTTPS 域名。
3. 后端按 2.3 部署，Nginx 反代 `/api`，CORS 白名单（**401 响应也必须带 CORS 头**，Q-037 教训）。
4. 健康检查：`GET /actuator/health` 的 `status=UP`（`rabbit` 不可用时为 `DOWN`，需确认是否阻断业务）。

### 2.3 生产部署（后端）

1. `cd 05_代码/backend/booking-service && mvn -q -DskipTests package` → `target/booking-service.jar`。
2. 初始化库：`mysql -h<host> -u<user> -p < db/init.sql`（幂等，可重复执行）。
3. 注入环境变量（见 2.4），启动：`java -Dfile.encoding=UTF-8 -Xmx512m -jar booking-service.jar`。
4. 校验：`/actuator/health`、`GET /api/packages`（total=4）、契约导出 `scripts/export_openapi.ps1`。

## 三、回滚方案

| 层 | 触发 | 回滚动作 | 影响面 | 时长（估） |
|---|---|---|---|---|
| 小程序版本 | 新版本线上故障 | 后台「版本回退」到上一版（首次发布无上一版时，重新上传旧包覆盖体验版） | 全量用户 | 5–15 分钟（需重新审核时更久） |
| 后端 | 新 jar 异常 | 保留旧 jar → `stop_all` → 替换 → 启动 → `health` UP + `packages` 200 | API 全链路 | 2–5 分钟 |
| 数据库 | 结构/数据错误 | `db_dump_*.sql` 恢复；`init.sql` 重建空库 | 预约数据 | 5–10 分钟 |
| 前端 H5 | 页面故障 | 回切上一版静态产物（Nginx 目录保留上一版） | H5 用户 | 1–2 分钟 |
| 缓存 | 脏缓存 | `redis-cli -p 6379 del ub:pkg:list` | 仅列表首屏变慢 | 秒级 |

> 真实线上回滚**未演练**（无线上版本），C09 证据 0/1。模板与步骤见 `10_交付/发布证据/发布与回滚记录.md` §2.4。
