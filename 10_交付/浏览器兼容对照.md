## 二、逐项对照（差异点 + 本项目处置）

| 检查项 | Chrome 实测 | 风险浏览器 | 本项目写法 | 处置/结论 |
|---|---|---|---|---|
| 横向滚动溢出 | `scrollWidth == clientWidth`（375/390/414） | 微信 X5（旧内核 `flex` 计算差异） | 全局 `box-sizing: border-box` + flex + `--gutter:24px`；无固定 width | Chrome 0 溢出；X5 未验，若溢出优先怀疑 `%` 宽度 + padding 叠加 |
| 安全区（刘海/底部手势条） | 无法在桌面验证 | iOS Safari、微信 | `base.css:76-77`：`padding-bottom: constant(safe-area-inset-bottom)` + `env(...)`；`base.scss` 同步 | 代码在；**真机未验**，上线前必须 iPhone 实测底部按钮不被遮 |
| 100vh 与移动端地址栏 | 桌面正常 | iOS Safari / 微信（地址栏收起时 100vh 偏大） | 6 页均用 `min-height:100vh`；未用 `dvh` | 风险已记录：真机上若出现「底部空一块/内容被顶」，改为 `min-height:100dvh` 并回退 `100vh` |
| 字体渲染 | 命中 `Source Han Serif SC / Noto Serif SC`（本机有），否则回落 `Songti SC/serif` | 微信/iOS 字体集不同 → 字重与行高观感差异 | `tokens.css:13-15` 三级回落链 | Chrome 正常；真机需看「宋体是否被替换成系统黑体」——若替换，标题气质会下降，属已知视觉风险 |
| CSS 变量 | 支持 | 微信 X5 5.0+ 支持 `var()` | 全站 token 走 CSS 变量（`tokens.css`） | 低风险；不支持时整站无色，属致命但不静默（一眼可见） |
| `-webkit-line-clamp` 折叠 | 正常（展开/收起实测） | 微信内置浏览器同为 WebKit，通常支持 | `detail.vue:239` 三行截断 | Chrome 实测 `clamp true→false`（`08_测试/evidence/ui_fold.json`） |
| `aspect-ratio` | 支持（但未用） | WXSS/旧内核不稳 | `detail.vue` 用 `padding-bottom:125%` + `height:125vw` 兜底 | 已规避，属主动兼容 |
| `gap`（flex gap） | 支持 | 微信 X5 旧内核不支持 flex `gap` | 只在 `privacy/index.vue:89` 用 `gap:6px`；`my` 桌面块用 `column-gap` | 低风险（隐私页为次要页）；若要彻底稳，改 margin |
| `position: fixed` 底栏 | 正常 | iOS 键盘弹出时 fixed 被顶起 | `detail.vue:253` 底部预约栏 fixed | 表单页提交按钮未 fixed（走 `padding`），风险已绕开 |
| `prefers-reduced-motion` | 支持，动效降级实测 | 微信不保证 | `LedgerVariant.vue` 媒体查询退化为终态 | Chrome 实测 4 档动效检出；微信端动效不影响功能 |
| 图片 `aspectFill` | — | 小程序 `image` 模式 | H5 用 `object-fit: cover`，小程序用 `mode="aspectFill"` | 双端各自实现，视觉一致（截图对比 375 已验） |
| console 报错 | 0（预走 17/17、探针 7/7） | — | favicon 已补（`src/static/favicon.png`） | Chrome 0 报错 |

## 三、结论

- **Chrome（375/390/414/1440）**：通过。横向溢出 0、首屏遮挡 0、console 0 报错、动效与折叠可用。
- **微信内置浏览器 / iOS Safari / Android 真机**：**未验证**。缺的是环境（真实微信 + 体验版 + 备案域名），不是代码。按基线 §4.5 属外部依赖，列入 C07–C09 同一降级包里。
- 已知会最先暴露的两处：① 底部安全区（iPhone 手势条遮按钮）；② `100vh` 在微信里偏大导致底部留白。两处修法已写在 §二，改动量 ≤ 2 行/处，不阻塞交付。
